## P0 · 一步标记（#7 + #8，合并做）

**待确认**

## P0 · 自定义列数（#2）

**现状**：`styles.css:1227` 与 `:2997`（分组网格）都是 `repeat(auto-fill, minmax(202px, 1fr))`，列数完全由窗口宽度决定，用户不能改；想看大图只能点开 Loupe。`main.ts:4793` 的 `gridColumns()` 用 `getComputedStyle` 数轨道，方向键 `↑↓` 会自动跟着列数走 —— **只改 CSS 变量，JS 不用动**。

**建议做法**：顶栏加一个列数控件（`− / 数字 / +` 或下拉 1 / 2 / 3 / 4 / 6 / 8），写 `--sp-cols`，两处 `grid-template-columns` 改成 `repeat(var(--sp-cols), minmax(0, 1fr))`；列数存 localStorage；快捷键可用 `[` `]`（注意 `[` 在 Loupe 里已是缩小，只在网格生效）。1 列 ≈ 单张看图但仍保留网格的标记 / 筛选 / 翻页，正好补上「要么六列要么一张」的中间档。

**代价**：列少了每屏张数下降、翻页变多；卡片高度随宽度变化，缩略图请求档位要跟着选（现在按 202px 定的），否则 2 列会糊。

## P0 · 找得到、进得来、出得去（#1）

**现状**：Windows 没有应用菜单也没有托盘图标 —— `lib.rs:2819` 的菜单是 `#[cfg(target_os = "macos")]`，里面才有 `.quit()`；单实例回调（`lib.rs:2901`）只做 `unminimize()` + `set_focus()`，**没有 `show()`**（`focus_main_window` 里有），窗口被隐藏时唤不回来；关闭主窗口的行为没自定义，走 Tauri 默认（关窗即退进程）。所以用户既找不到退出，也不确定关掉后该从哪里再打开。

**建议做法**

1. 加系统托盘图标，右键菜单至少两项：**显示主窗口 / 退出 S·P**；左键 = 显示并聚焦。Windows 尤其需要，macOS 可保留原生菜单 Quit 但托盘仍提供「显示主窗口」。
2. 单实例回调与托盘「显示」统一走 `unminimize → show → set_focus`（对齐 `focus_main_window`）。
3. 关于页或顶栏给一个明确的「退出 S·P」入口（Rust 命令 `app.exit(0)` 最稳，不依赖 `process:allow-exit` 权限）。
4. **先定清楚关闭窗口的语义**（见下方待确认），并在关于页写一句说明。

**实现结果（第二批）**

- **关窗语义按「收进托盘常驻」执行**：主窗口 `CloseRequested` → `prevent_close()` + `hide()`，托盘图标常驻；真退出走托盘菜单「退出 S·P」（macOS 也可 ⌘Q）。这是同时治「找不到退出」与「切走后找不到入口」的唯一组合 —— 真退出的话，窗口一关托盘也一起没了。
- 托盘左键 = 显示主窗口，右键 = 「显示主窗口 / 退出 S·P」；图标复用打包的默认窗口图标，不新增资源。`Cargo.toml` 给 `tauri` 打开 `tray-icon` feature。菜单事件只注册一份全局 handler，同时处理 macOS 应用菜单的「关于」。
- 托盘唤起、单实例二次启动、关于页聚焦统一走 `show_main_window()`：macOS 先 `app.show()`（整个应用可能被 Hide），再 `unminimize → show → set_focus`。
- 顶栏 / 关于页**不再**加退出按钮：托盘菜单已给出唯一明确出口，再加一处只会让简洁模式更挤。
- **待实机验**：Windows 11 新托盘图标可能默认折叠在「隐藏图标」里；`×` 隐藏后进程常驻是否符合预期；自动更新 `relaunch()` 后是否只剩一个托盘图标。

## P0 · 拖文件夹导入（#6）

**现状**：前端没有任何 `drag`/`drop` 监听，`tauri.conf.json` 也没显式设 `dragDropEnabled`。`default.json` 权限是 `core:default` + 四个插件默认集。

**建议做法**：前端用 `onDragDropEvent(...)`（Tauri 2），「拖入时」给全屏高亮 + 「松开以导入此文件夹」，「放下时」拿到路径 → 校验是目录 → 复用现有 `scan_folder` 与范围选择弹窗（子目录仍要问一次范围）。顺带支持拖单张 NEF/JPG 时打开其所在目录。多目录一次只取第一个；拖入非目录忽略。

**实现结果（第二批）**

- `tauri.conf.json` 显式 `dragDropEnabled: true`；前端用 `getCurrentWindow().onDragDropEvent()` —— Tauri 2.12 的 `Window` 自带这个 API，不必引入 `getCurrentWebview`。`core:default` 权限已够，`capabilities` 未改。
- 提示层 `pointer-events: none`，**绝不吃掉原生 drop 事件**；浏览器预览里另用 `dragover` / `drop` 的 `preventDefault()` 挡住「浏览器把文件当导航打开」。
- 新增 Rust 命令 `folder_from_drop`：目录直接返回；照片文件（复用 `pairing::classify`）返回其父目录；其它文件与不存在的路径一律拒绝。路径判断放后端，Windows 反斜杠交给 `std::path`，并加了单元测试覆盖四种情况。
- 把 `pickFolder()` 拆出 `useFolder()`，拖入与按钮选文件夹共用：子目录范围弹窗、localStorage、扫描行为完全一致。扫描中或范围弹窗未关时拒绝导入；首次键位卡会在成功导入时自动收起。
- **待实机验**：Windows 上 `drop` 事件是否稳定带回 `paths`（无头浏览器模拟不了原生拖放）；多文件夹一次只导入第一个。

**代价 / 注意**：原生拖放启用后，HTML5 拖放（网页内拖元素）在 Windows 上会被 Tauri 接管；本应用只用文件拖入，没有冲突。

## P1 · 画质判定与直方图（#3）

**现状**：`analyze.rs:67-95` 把图缩到工作尺寸后算**全图**拉普拉斯方差（清晰度）+ 灰度 `≥250` / `≤5` 的**全图像素占比**；阈值硬编码且前后端各一份（`main.ts:836-838` 与 `lib.rs:723-732`），经验值，代码注释自己都写了「待真素材校准」。没有直方图 UI。

**为什么会误判**：浅景深人像背景大片平滑，会把全图方差拉低 → 判「糊」；逆光天空 / 白纱 / 高光点占比超过 2% → 判「过曝」。两个指标都是「全图统计量」，天然分不清「主体清晰 + 背景虚化」和「整片没对上焦」。

**建议做法（分两步）**

1. **先给判断依据**：大图详情加 RGB + 亮度直方图（可折叠、默认收起不挡图）；侧栏「画面质量」把徽标从结论改成「疑似」并展示具体数值。
2. **再修算法**：清晰度改成分块评估（3×3 或 5×5，取最清晰块 / 中心加权），而不是全图方差；高光溢出改成「连续高亮区域面积」或至少排除零散小高光。
3. 阈值若要交给用户调，必须**由后端统一存一份**并同时用于筛选 SQL、分面计数、卡片徽标，否则会出现「侧栏说 12 张过曝、网格里只有 8 张」这种前后端口径不一致（现有代码注释已强调过这点）。

**代价**：改算法会让旧库的分析值失效，需要一次重新分析（可沿用现有的后台分析任务与取消开关）；直方图要读原图预览像素，别在滚动路径上做，只在打开详情时算一次。这块是 8 条里唯一需要拿真实素材反复校准的，别顺手做。

**实现结果（第三批）**

- **清晰度改成分块**：`sharpness_score()` 把缩到 256px 的灰度图切成 8×8 块，各算拉普拉斯方差，取最清晰 25% 块的**中位数**（抗水印 / 局部噪点），再与全图分数 8:2 融合。浅景深的大片虚化背景不再把锐利主体拉成「糊」；纯色图依旧判糊，单测两头都覆盖。
- **过曝口径收紧**：溢出占比门槛 2% → **5%**（2% 时白墙、雪、逆光天空几乎必报）。所有徽标、分面、详情文案统一降级成「**疑似**」，明确写出「机器初筛 · 以肉眼和直方图为准」。
- **阈值单一来源**：新增 `quality_config` 命令，把三个门槛与算法版本从后端下发给前端，删掉 `main.ts` 里硬编码的那份；筛选 SQL、分面计数、卡片徽标现在都读同一组常量，不会再出现「侧栏 15 张、筛出 12 张」。
- **旧库自动重算**：`photos` 加 `analyze_version` 列；启动时 `invalidate_outdated_analysis()` 把旧版本行的三项指标清成 NULL，后台分析趟照旧挑「没算过」的重算并写入新版本号。启动时的静默重扫即使 `changed === 0` 也会触发一次分析，保证升级后徽标不会一直空着。
- **直方图**：大图底栏「直方图」按钮 + `H` 键，左上角面板画 RGB 三通道曲线与亮度填充（计数开方压缩，避免大片纯白把其余桶压平）。数据走新命令 `photo_histogram`，按库内 id 取路径、只解码内嵌预览、**不接收任意路径**；翻页自动刷新并用 `histForId` 丢弃过期响应。状态写 `localStorage["sp:histogram"]`，两种界面档位都保留这个按钮。
- 顺手修掉一处浅色主题老问题：右上角缩放控件是玻璃底 + 写死的浅色文字，浅色主题下白底白字看不见；现在浅色档改成白底深字。
- **仍未做**：阈值没有开放给用户调，也没有拿真实 NEF 素材跑分布校准（用户手上有样片目录时再做）。直方图是 512px 内嵌预览算的，与分析用的 256px 采样不同，数值可能有微小差异，所以面板只给曲线和一句判读提示，不显示百分比去和侧栏数字对账。

## P2 · 横竖图分组（#4）

**有没有用**：有用，场景是「竖图挑出来发社媒 / 横图做壁纸」这类批量筛选，比一张张翻方便。

**成本修正（第三批核对代码后）**：原先判断「得改 schema」是错的 —— `photos` 表扫描时就已经写入 `width` / `height`（`indexer.rs` 的 INSERT 里有），`photo_detail` 也是直接读这两列，不是打开详情再现读 EXIF。真正缺的只是：`PairCard` 没返回方向、没有分组依据、没有分面。所以这更像「查询加一个派生字段 + 前端加一个分面」，**不必新增列、不必重扫**。横竖可以用 SQL 表达式算，不落库。

**注意**：竖拍的 EXIF Orientation 会让原始宽高是「横」的，比较前得按旋转标记归一化（`orientation IN (5,6,7,8)` 时把宽高对调），否则竖图全被算成横图；`p.orientation` 这一列已经有了。正方形（`width = height`）建议单列一档，别硬塞进横或竖。

**实现结果（第四批）**

- **一段 SQL 覆盖三处口径**：`shape_key_sql()` 产出 `landscape / portrait / square / unknown`，筛选条件、侧栏分面计数、列表卡片字段全部引用它，不落库、不重扫。宽高差在平均边长 2% 内算方图。
- **分组与筛选都给了**：分组依据下拉加「按横竖图分组」；侧栏加「画幅方向」四档，和焦段 / ISO 一样复用多选分面（同维 OR、跨维 AND），支持 chip 单独摘掉与一键清除。简洁模式按既有规则把这一栏视为高级分面藏起来，但筛选生效时 chip 与「清除筛选（N）」常显；专业模式选过「按横竖图分组」再切简洁，分组依旧生效（只切可见性）。
- **实测发现并修掉一个会让功能白做的问题**：用户手上的 Z50II NEF 把像素尺寸写在 **SubIFD 的 ImageWidth/Length**，而索引只取 ExifIFD 的 `PixelXDimension/YDimension` —— `width/height` 全是 NULL，只有 `Orientation=8`。若只按宽高判定，整批照片都会落到「尺寸未知」。现在尺寸缺失时**退化用 Orientation**：5–8 判竖图、1–4 判横图、读不到才 unknown。
- **端到端验证**：拿 `~/Downloads/LANDrop/我宝/DSC_5292.NEF` 真跑了一次索引，结果 `(width=None, height=None, orientation=8) → portrait`，分面 `portrait=1`；单测另覆盖了竖拍旋转、方图、未知尺寸、非法筛选值。
- **已知限制**：尺寸和 Orientation 都读不到的照片归「尺寸未知」；尺寸缺失时无法区分方图（会按 Orientation 归到横或竖）。这类照片多数是 EXIF 被后期工具重写过的 JPG。

## P0 · 一键切换「简洁 / 专业」（#5）

用户拍板：**做一个一键切换按钮**，而不是只靠渐进披露。

原先的顾虑是「两套模式 = 两套代码，长期欠维护」。这个顾虑可以用一条硬边界规避掉：**开关只切「可见性」，不切「逻辑」**。底下始终是同一套 DOM、同一套状态、同一套写库路径与快捷键，极简模式只是挂一个 `data-mode` 让 CSS 把高级控件藏起来。新增控件时只需要决定它归哪一档，加一条选择器，不存在两份实现要同步。

**入口**：顶栏右侧、深浅色按钮旁，一枚 `简洁 / 专业` 图标按钮（带 `aria-pressed` 与 tooltip，显示当前档位）；切换给一句 toast「已切到简洁模式，高级功能仍在，快捷键照用，再点一次切回」。状态写 `localStorage["sp:ui-mode"]`，重启保持。

**两档差异**（按 `index.html` 现有控件列，实现时照单归位）

| 区域 | 简洁模式 | 专业模式 |
|---|---|---|
| 顶栏 | 选择文件夹、模式开关、深浅色、关于 | 全部：+ 重新扫描 / 清理 / 连拍 / 清空 / 撤销 / 重做 / 分组依据 |
| 工具栏 | 搜索、计数、列数（#2） | + 排序下拉 |
| 侧栏 | **默认收成 44px 窄轨**（可手动展开）；展开后只显示状态 / 星级 / 色标 | 现在这套，全部分面展开 |
| 已生效筛选 | **chip 常显 + 一键清除**（关键，见下） | 现有「已选条件区」 |
| 选片操作栏 | 保留 / 淘汰 / 星级 / 导出 | + 清除 / 全选 / 反选 / 取消 / 批量 ▾ |
| 大图 | 详情 / 直方图默认收起 | 全功能 |
| 默认列数 | **2 列**（正好呼应 #2） | 沿用当前自适应 |
| 首次启动 | 一屏键位卡 `P` `X` `1-5` `⌘Z`（只显示一次） | 不弹 |

**三条不能破的边界**

1. **不销毁 DOM、不清 filter / selection / groupMode**：切模式只是换 CSS，切回来原样恢复；被藏起来的功能快捷键照常可用（`⌘Z`、`P`/`X`/`U`、`1-5`、`I`、`F`、`\` …），别让熟练用户反而变慢。
2. **筛选藏了，入口不能藏**：简洁模式下侧栏收起，但只要有筛选生效，常显 chip + 「全部清除」——否则就是 #1「找不到在哪」的重演。同理**不藏**：更新面板、扫描进度、错误横幅、导出对话框、缓存占用入口。
3. **两档列数各存一份**：切模式不要覆盖用户手动设过的列数；只在首次进入简洁模式时给 2 列默认值。

**与第一批的联动**：#2 的列数控件、#7 的 hover 星级条、#6 的拖放提示、#1 的托盘「显示主窗口」在简洁模式下都保留；它们本身就是主路径的一部分，不算高级功能。

**实现时定下的几处细化**

- `markTargets()` 的优先级是「大图当前 > 多选的那批 > hover 卡片 > 单选卡片」。**多选时批量意图优先**，否则鼠标随手一放就会把「选中 30 张一起打星」变成只标一张。
- 卡片星级条用 `elGrid` 上一个 click 委托处理，`applyPatch(..., false)` 走单张分支（不清空选择、不误报「已批量」）；双击星级条不会打开大图。
- 列数两档各存一份（`sp:cols:simple` / `sp:cols:pro`），`[` `]` 在网格里调列数；1 列时网格缩略图改请求 1600 档（512 会被拉糊），2 列仍用 512。
- 简洁模式下侧栏默认收起，但工具栏的 `清除筛选（N）` 常显，就是「筛选藏了出口不藏」那条边界的落点。
- 首次键位卡只在「没有 `sp:ui-mode` 且没有历史图库」时出现一次，Esc / 点遮罩 / 点按钮都能关，弹出时全局快捷键不穿透。

**后续升级（用户追加需求）：从两档预设升级成「功能页」逐项开关**

用户试用后提出：两档不够灵活，希望有一个页面把**所有操作功能列出来，自己勾选只显示哪些**。已实现，要点：

- 原来写死在 CSS 里的 `html[data-mode="simple"] #id` 隐藏清单，升级为**按功能键开关**：每个控件标 `data-feature="key"`，启用清单整体写在 `<html data-features>`（空格分隔），CSS 一条规则一个键。`data-mode` 只保留给「清单还没写入时的首帧兜底」，防止升级后闪一下全部按钮。
- 顶栏按钮从「简洁 / 专业」切换改为「**功能**」入口，点开（或 `⌘/Ctrl + ,`）弹出一页清单：34 个可开关控件按「顶栏与文件 / 选片操作 / 左侧筛选 / 大图查看」四组列出，每组带 `n/N` 计数；「简洁」「专业」变成页内两个预设按钮，动任何一项就变成「自定义」。
- 开关清单持久化在 `localStorage["sp:features"]`；旧版只有 `sp:ui-mode` 时按原档位迁移，认不出的键直接丢弃。各档列数照旧各存一份（新增 `sp:cols:custom`，从离开的那档继承，换档不让图突然变大变小）。
- **边界不变**：选择文件夹、导出、清除筛选、关于 / 更新入口不在清单里、永远显示；已生效筛选的 chip 与「清除筛选（N）」常显；被藏起来的功能快捷键照常可用。
- 加新控件的成本仍然是两行：HTML 标 `data-feature`，`main.ts` 的 `FEATURES` 清单登记一行（自动进功能页）。
