## 1. 界面速览

界面的核心判断是：**照片是主角，其余一切都退到后面**。网格里除了图什么都不抢眼，只有「配对缺失」这种真需要你看一眼的信息才给彩色徽标。

## 2. 从导入到导出

**选文件夹时会先问范围**：如果里面还有子文件夹，会弹出一张勾选表——默认全选，即整目录递归；只想看这个文件夹自己的照片就**一个都不勾**（只读这一层、不进子文件夹）；只要某几个子目录就只勾它们。勾选结果会记住，之后点「重扫」沿用同一范围。没有子文件夹时不弹表，直接扫。

> 已知取舍：勾了子目录就**不包含根目录自己那一层**的照片——要么都不勾（只看这一层），要么全勾（递归）。混着来需要给每个目录各配一个扫描层数，弹窗里加一行「（当前文件夹里的照片）」勾选项即可。

**选完即扫，边扫边出图**：入库按批次提交并每批释放数据库连接锁，网格先铺出已入库的前 N 张，过程中可以照常滚动与标记。启动时自动恢复上次的图库，先用已有索引铺图，再后台增量重扫；文件没动过就不重排界面（不闪）。

**主区是分组视图**：照片按顶栏「分组依据」下拉选的维度收组（组名吸顶、可折叠）。文件夹、选片状态、星级、文件类型、拍摄日期、机身、画面质量、镜头、焦段、ISO 都能当依据；文件夹分组显示相对路径，子文件夹自带母文件夹。点任意一张进单张大图（Loupe）看细节、按 `P`/`X` 标去留。

**按错了直接撤销**：`⌘Z` / `Ctrl+Z`（或顶栏「撤销」）一步步退回，`⇧⌘Z` 再往前一步，最多各 50 步；批量标记和连拍里一次改一组也是一次退干净。撤销走的是和正向标记同一条写库路径，侧栏计数、筛选、导出全都跟着动。

**顶栏「清空」**回到未选文件夹的状态：不删原片、不碰索引库，选片标记也原样留着，重扫同一个文件夹会自动回到照片上。

**换文件夹不会串台**：旧文件夹的照片会故意留在库里（为了标记能复用），但界面只显示当前文件夹范围内的照片，导出和左侧计数同理。

**导出**：按筛选范围把原片**复制**到目标文件夹，可选「仅 RAW / 仅 JPG / 两者」或「只导出当前选中的这几张」，文件名按模板重命名（`{name}`/`{date}`/`{time}`/`{seq}`/`{stars}`/`{camera}`/`{pair}`），重名加后缀、同大小跳过，并生成带 BOM 的 CSV 清单。只读原片，绝不删除或移动。

## 3. 筛选与侧栏

左侧筛选栏覆盖：选片状态 / 星级 / 色标 / 画面质量 / 文件类型 / 拍摄日期（按月份分组）/ 焦段 / ISO / 机身 / 镜头 / 文件名搜索 / 五种排序，每一项都带图库范围内的计数。

- **多选**：同一维里可以勾好几个值（两支镜头、好几天、几档 ISO…），**同维取并集、跨维取交集**（「11 月 8 日 + 保留 + 180-600」）；再点一次已选项＝取消，点「全部」＝清空这一维，不用专门跑去找「全部」那一项。
- **已选条件区**：每个选中的值一枚 chip，带维度名、点一下单独摘掉，旁边「全部清除」一次清空（工具栏「清除筛选」同效）。选得多时列表内滚动并做底部渐隐，长镜头名折两行不被截断。
- **两层折叠**：点顶部「筛选」把手（或按 `\`）把整栏收成 44px 窄轨，网格自动变宽；窄轨上的数字徽标是生效中的筛选条件数。每个分面组标题也能单独折叠（键盘 `Enter` / 空格同样可用）。两个状态都记在 localStorage，重启保持；有筛选生效的那一栏会自动展开。
- **计数口径**：是**整个图库**，不是「在当前结果里再数一遍」。这样点开侧栏看到的数字始终稳定，不会因为叠加条件而缩水到看不懂。
- **镜头栏只要有照片就在**：标题显示当前图库有几支镜头，超过 6 支先收起尾巴，点「显示全部」摊开，选中的镜头自动展开到可见；读不到镜头型号的照片归到「未知镜头」，也能单独筛掉。
- **拍摄日期按月份折叠**，默认只展开最近两个月——几百天全铺开会翻到崩溃。筛选到某个日期时，它所在的月份会自动展开。
- **机身时间偏移校正**：侧栏「机身」标题后的「时间校正」，多机身时钟不同步时给快的那台填负数，排序与连拍分组立刻按校正后的时间重算（只在读到两台以上机身时出现）。
- **画面质量**：扫描结束后后台算清晰度（拉普拉斯方差）与过曝 / 欠曝（直方图），结果进侧栏和排序，有问题的照片左下角带徽标（悬停看得到具体数值）。阈值（清晰度 25 / 过曝 2% / 欠曝 25%）还是经验值，待真素材校准。

**批量标记**：操作栏「批量 ▾」对**当前筛选出来的全部照片**（含还没滚出来的那些）一次性标保留 / 淘汰 / 清除 / 打星——比如「ISO 6400 以上全标淘汰」不用一张张点，一次 `⌘Z` 整批退回。

**选片进度**：页脚显示「已过目 312 / 1000（31%）· 保留 48」。口径是当前文件夹的**全部**照片，不跟着筛选变；打了星也算过目。

## 4. 大图、缩放与详情

点卡片进单张大图，`←` `→` 翻页、`Esc` 关闭，里面同样能标记与打星。

- **缩放**：滚轮（以鼠标为锚点）、双击切换、放大后拖拽平移，`+` `-` 缩放、`⇧F` 复位、`A` 到 1:1、`F` 全屏；右上角控件条显示当前倍率。`1:1` 是一个图像素占一个屏幕像素——判断有没有对上焦就用它。放大超过 1 倍才去生成 4096px 那档，**倍率和平移不变，只是变清晰**；翻页自动回到整图。
- **详情面板**（`I` 或「详情」按钮，默认收起不挡照片）：文件属性（长路径点击即复制）、**完整 EXIF**（打开时现读原文件，枚举值译中文：曝光程序 / 补偿 / 测光 / 闪光灯、镜头型号与序列号 / 等效焦距、机身序列号 / 固件、色彩空间 / 白平衡、时间与时区、GPS 坐标与海拔、描述 / 作者 / 版权 / 备注）、画面分析分数、同组 NEF/JPG 文件（标注原文件是否还在）。
- **对焦框**（大图里 `O` 键或「对焦点」按钮，**默认关**）：把相机按快门时真正用上的那一块画在大图上，缩放时跟着走。数据来自尼康 MakerNote 的 AFInfo2，是传感器原始像素坐标；读不到（非尼康 / 机身没写）就不画、不报错。其他机身目前读不出来，各家 MakerNote 格式各异。
- **分页加载 + 视口外卸载位图**：滚到哪读到哪，滚出 2400px 的卡片把解码后的位图还给系统（数据 URL 仍在内存缓存里，回来时秒恢复），几千张不会撑爆内存。

## 5. 连拍对比与色标

**连拍聚类与对比选片**：按拍摄时间间隔自动把连拍聚成组（1 / 3 / 10 秒档位可调）。对比网格里点一张只切换这一张，**同一组可以保留多张**；`Shift` + 点击（或 `Shift` + `1`-`9`）＝只留这张、其余淘汰，「清空本组」一键回到未标记，`Esc` 退出。顶部实时显示「已保留 N 张」，导出按 `decision` 筛选，同组多张保留会全部导出。

**色标**：保留 / 星级之外的第三条轴。同一批照片里「要修的」「要发的」「给客户看的」常常重叠，星级一旦被拿去表示去留，就再也腾不出手表达批次——色标颜色本身不表意，你定它是什么意思。

- 键位：`6` `7` `8` `9` 分别是红 / 黄 / 绿 / 蓝，**减号 `-` 是紫**（`0` 已是清除星级、`1`-`5` 是星级，第五个色没有数字可用，就挂在它在键盘上的邻居身上）；再按一次同一个键＝取消。大图底栏有五个色点，卡片左边一条竖色带，侧栏可按颜色筛、详情面板显示当前色。
- **和星级、去留完全独立**：标红色不动决策也不动星级，`⌘Z` 一步退掉整批，清色标不会误删评分。老库升级不用做任何事，色标列会自动补上。

## 6. 缓存与清理

**缩略图缓存会一直长大**，页脚右下角实时显示占用（缩略图 + 索引库合计）。放大查看过的照片还会多一份 4096px 高清档，是增长最快的一项。

点占用数字、或顶栏「清理」，打开三档清理面板：只清缩略图最安全；连照片索引一起清（**选片标记保留**，重扫后自动回到照片上）；全部清空（连保留 / 淘汰和星级一起删，不可恢复）。缓存另有 2GB 水位线自动 LRU 淘汰。全程不碰原片。

| `0`–`5` | 星级（`0` 清除） |
| `6` `7` `8` `9` `-` | 红 / 黄 / 绿 / 蓝 / 紫色标，再按一次取消 |
| `⌘Z` / `⇧⌘Z` | 撤销 / 重做（最多各 50 步） |
| `⌘` 点 / `Shift` 点 / `⌘A` | 网格多选 / 范围选 / 全选（另有反选） |
| `←` `→` / `Esc` | 大图翻页 / 关闭 |
| `I` / `O` / `F` | 详情面板 / 对焦框 / 全屏 |
| `+` `-` / `⇧F` / `A` | 缩放 / 复位 / 1:1 |
| `1`–`9` / `Shift`+`1`–`9` | 连拍对比：选中该张 / 只留该张 |
| `\` | 收起 / 展开左侧筛选栏 |
| `[` `]` | 网格里减 / 增一列（大图里 `[` 仍是缩小） |
| 鼠标悬停 + `1`–`5` | 直接给指向的那张打星，不用先点选 |

**一步标记（不用先点小图）**：鼠标停在哪张卡片上，按 `P` / `X` / `U` / `1-5` / 色标键就作用于那张；hover 时卡片浮出 5 颗可点的星和 `0`（清除），点一下即写库、`⌘Z` 可撤销。选中两张以上时以「选中的那批」为准，免得鼠标随手一放把批量标记变成单张。当前目标有一圈细边框，和「选中」的外描边叠在一起也能分清。

**自定义列数**：工具栏 `− / 当前列数 / +`，点中间那颗回到「自动」（按窗口宽度排）；范围 1–8 列，网格里 `[` `]` 也能调。两种界面档位各记各的列数。1 列时缩略图自动改请求 1600px 档，不会被 512px 拉糊。

**简洁 / 专业一键切换**：顶栏「简洁 / 专业」按钮只切控件的可见性，不换界面逻辑、不清筛选 / 选择 / 分组，被藏起来的功能快捷键照常可用。简洁档默认 2 列、侧栏收成窄轨，只显示状态 / 星级 / 色标三个分面；筛选一旦生效，工具栏「清除筛选（N）」常显，不会筛完找不到出口。全新安装默认简洁，已有图库的老用户升级后保持专业。首次启动弹一屏键位卡，只出现一次。

更多键位设计与取舍见 [`DESIGN.md`](DESIGN.md)「五、键盘快捷键设计」。

## 8. 彩蛋

默认关：连点顶栏 logo 5 次开启（再连点 5 次关闭），只写 localStorage，不碰数据库 / 标记 / 导出。开启后：空状态显示一句摄影名言、一整批「未标记」归零时页脚轻弹一下、`⇧D` 切暗房安全灯、`↑↑↓↓←→←→BA` 给卡片套上胶片齿孔边框。「关于」窗口里按住 `⌥` 还藏着一句话。

**暗房会给整屏蒙红，仅用于夜间浏览，别拿它判断照片色彩**；只在当前会话生效，重启自动恢复正常。

## 9. 常见问题与故障

**macOS 双击提示「应用已损坏，无法打开」**：应用只有 ad-hoc 签名，从浏览器下载的文件带隔离属性，右键 → 打开也不管用。拖进「应用程序」后执行：

```bash
xattr -cr "/Applications/S·P.app"
```

Windows 同理会有 SmartScreen 提示，点「仍要运行」。

**检查更新 / 下载更新包失败**：v0.4.3 起面板会显示分类后的中文原因（网络被网关拦截、验签失败、无权限替换 app、其它）并附原始错误摘要。已知本机到 `github.com/.../releases/download/` 的大文件会返回 `504 Gateway Time-out`，清单能取到但更新包下不动——产物本身无损，直接从 [Releases](https://github.com/Joker-desire/SP/releases) 手动装对应 dmg / msi 即可。排查过程见 [`AUTO_UPDATE.md`](AUTO_UPDATE.md) 第 6 节。

**窗口被挡住时缩略图几乎不加载**：WebKit 会暂停后台渲染，那是浏览器省电策略，不是卡住。切回前台就恢复。

**双击启动没反应**：启动阶段任何硬退出都会写进数据目录的 `startup-error.log`，下次启动成功自动删掉。三层兜底见第 11 节。

**数据在哪**：macOS `~/Library/Application Support/SP/`，Windows `%APPDATA%\SP\`。删应用不会删照片，原片全程只读；重装后标记还在（按 `pair_key` 存，换盘、挪目录、重建索引都不丢）。

## 10. 自动化的部分

| 动作 | 之前 | 现在 |
|---|---|---|
| 选文件夹 | 选完还要点「扫描建索引」 | 选完即扫，扫完直接出图 |
| 打开应用 | 每次都要重新选文件夹 | 自动恢复上次的图库，先铺图再增量重扫 |
| 新拷进来的照片 | 要手动点扫描 | 启动时自动增量扫描，发现新增；没变化则不重排界面 |
| 滚动 | 只显示最近 200 张 | 滚到底自动续载，直到取完 |
| 内存 | 每张卡片的位图一直挂着 | 滚出 2400px 就释放，滚回来秒恢复 |
| 扫描过程 | 要等全部扫完才一次性出图 | 边扫边铺，过程中可以照常滚动与标记 |
| 换文件夹 | 上一个文件夹的照片还会混在网格里 | 视图随文件夹走；旧记录留着复用标记，但不再出现在界面上 |

```
启动 → 读 localStorage 里的文件夹
     → 先用已有索引把网格铺出来（不等扫描，秒开）
     → 后台增量重扫（文件没变的话是纯 stat，一两秒）
     → 有变化才重排界面
```

**「自动重扫」之所以敢在每次启动都做，靠的是增量扫描的快路径**：先比「文件大小 + 修改时间」，一样就跳过，连文件内容都不读。退化成读内容的话，几千张就是几个 GB 的读取，这个功能就不成立了。`indexer.rs` 里有一条测试专门守这个性质（把库里的指纹故意改错，验证扫描仍然走快路径）。

## 11. 实现细节

### NEF 为什么能显示：抠内嵌预览

RAW 是容器格式，浏览器内核天生解不了——**任何选片工具想显示 NEF，都必须自己想办法拿到像素**。完整解码 RAW（demosaic）很慢，这里走另一条路：**相机写 NEF 时已经顺手在文件里存了一张全尺寸 JPEG 预览**，抠出来直接用。

- 比完整解码快得多，不需要 demosaic——选片只需要看图，不需要像素级正确
- 色彩是那台机身的原味（相机自己渲染的）
- 和相机型号无关，**任何 RAW 格式都吃得下**（CR3 / ARW / RAF / DNG 同理）

算法在 `thumb.rs`，关键点：**不能简单找「SOI 之后的第一个 EOI」**。RAW 里的预览自己带 EXIF，而 EXIF (APP1) 里可能又嵌着一张小缩略图；按标记段正确解析才不会撞上那张小图的 EOI 截出残缺数据。测试里专门造了一个「嵌套缩略图」样本。

抠出的是全尺寸 JPEG 预览（多数机身五千到六千像素宽，几十到几百 KB），三级缩略图（160 / 512 / 1600，放大时按需再加 4096）再由它依次缩出。抠不到内嵌预览时自动降级：标准位图解码 → RAW 解码（rawler + 轻量 demosaic）→ 占位图，路由写回 `photos.decode_path`。

### 性能：为什么必须给依赖开优化

同一张 NEF，从「抠预览」到「三级缩略图落盘」，debug 构建比 release 慢一个数量级（二十倍上下），而 `tauri dev` 跑的正是 debug。所以 `Cargo.toml` 里有：

```toml
[profile.dev.package."*"]
opt-level = 3
debug-assertions = false
overflow-checks = false
debug = false
```

只优化依赖、自己的代码保持快速增量编译。另外两道防止内存被打爆的闸门：前端只请求视口内缩略图并排队限制 4 路并发；Rust 侧还有 `Limiter`（`thumb::global_limiter`），因为一张四千多万像素的预览解码成 RGB8 就要一百多 MB。

**吞吐取决于素材本身**：瓶颈是「整张预览解码」，而这一步能并行——4 路并发下几千张可以边滚边补，不需要等全量生成完。关键在于**按需生成**：你只为你真正看过的照片付解码成本。

想量自己素材：

```bash
SP_SAMPLE_DIR=/path/to/shoot cargo test thumb_throughput -- --ignored --nocapture
```

**还能再快的地方**（暂未做）：目前是「整张解码 → 再缩放」，而解码全尺寸预览就是绝对大头。JPEG 支持按 1/2、1/4、1/8 直接解码（DCT 尺度变换），做 512px 网格图时只解 1/4 就够，足够再快好几倍；代价是要绕开 `image` crate 直接用 `zune-jpeg` 的 scale 选项。等素材量大到滚动跟不上了再做。

**约定**：所有跨进程调用都收在 `src/main.ts` 里，Rust 命令和前端调用一一对应，改接口时两边一起改。

### 启动失败时不会「没反应」

双击启动看不到终端输出，所以启动阶段的硬退出对用户等于「点了没反应」。三层兜底：

1. **能自愈的就自愈**：上次在写入过程中被杀掉会留下「0 字节库 + 热 journal」，SQLite 恢复流程要删掉那个 journal，删不掉就会一直失败。现在小于一页的文件（不可能是有效数据库）直接丢弃、附属文件一起清掉、原地重建；够一页的一律**改名隔离**（`library.db.bad-<时间戳>`）而不是删除。
2. **实在打不开就把应用撑起来**：退回内存库，界面给一条红色横幅写清路径和原因，能看能操作，但明确告诉你「本次运行不会保存索引」。
3. **线索落盘**：启动异常写进数据目录的 `startup-error.log`，下次启动成功自动删掉。

另外 WAL 不可用会自动降级为默认日志模式。

### 几个关键技术决定

- **文件指纹不做全文件哈希**：一张 NEF 三四十 MB，几千张就是上百 GB 读取量。改用「文件大小 + 修改时间 + 前 1MB 内容哈希」，快 50-100 倍。
- **`photos` 每个文件一行，用 `pair_key` 聚合**：而不是「一个配对一行、两个路径字段」——后者遇到「某次只拍了 JPG」就要写特例。配对逻辑只存在于查询和界面层。
- **工作集按 `pair_key` 而非 `photo_id`**：对用户来说「一次快门」才是最小单位。
- **`decisions` 与 `photos` 分表**：主键是 `pair_key`，照片换盘、挪目录、重建索引都不会丢标记。
- **原片只读是架构保障**：前端 WebView 没有任何文件系统权限，所有磁盘操作必须经过 `src-tauri` 里显式暴露的命令，前端就算有 bug 也碰不到照片。

> 两条来自真实踩坑的教训：

> 1. 早期测试全走内存库（`open_in_memory`），`open()` 的文件路径分支从没被执行过——而它恰恰是启动时唯一会碰的地方。

合成样本证明不了「真机能用」——不同机身的 NEF 布局、内嵌预览尺寸都不一样，换机身时跑一次，它打印抠出的预览尺寸和各级缩略图的耗时与体积。
